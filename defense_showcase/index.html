阶段目标：从岗位理解到结构化面试

让 AI 面试建立在岗位画像和简历证据之上

本项目不是单点问答工具，而是围绕招聘评估链路构建的闭环系统：人才画像定义“要评估什么”，简历分析整理“候选人已有证据”，AI 面试据此生成问题、追问与记录，最终沉淀可复盘的评估结果。

系统闭环概览

人才画像：定义岗位评估标准

通过对话和 JD 解析，沉淀岗位职责、信号维度、任职条件与排除画像。

简历分析：抽取候选人证据

从简历、GitHub、博客等材料中拆解经历、技能、项目成果和信息盲区。

转换存储：统一面试输入

画像和简历结果经转换器写入面试画像库、候选人库和记录目录。

AI 面试：动态提问与追问

将画像信号与简历证据合并，生成语音面试问题、追问策略和记录结果。

数据流程图

这张图展示系统中数据如何从原始材料进入各业务模块，如何经过转换器沉淀为统一输入，最终驱动 AI 面试和评估复盘。

原始输入

招聘需求 / JD

岗位背景、职责边界、技能要求、团队现状、招聘风险点。

候选人材料

PDF、Word、图片简历，以及候选人提供的 GitHub、博客链接。

智能解析

画像 Agent

解析 JD 并通过对话补齐信息，生成结构化 JobProfile。

简历流水线

文本抽取、清洗、LLM 语义分析、OCR 回退和外部足迹挖掘。

结构化结果

岗位画像

信号维度、必须条件、加分项、反向画像、通用追问建议。

候选人证据

能力声明、客观经历、项目证据、盲点、GitHub/博客信号。

转换与存储

画像转换器

portrait_to_interview_profile() 写入面试画像库。

候选人转换器

resume_to_interview_candidate() 写入候选人库。

面试输出

动态面试

基于 profile_id 和 candidate_id 生成问题，执行语音/文字交互。

评估记录

保存问题、回答、追问、评分、推荐结论和原始快照。

关键闭环：画像提供“评价标准”，简历提供“候选人证据”，转换器保证两个上游结果能被面试引擎消费，面试记录再把过程和结论沉淀为可复盘数据。

一句话总结

整体技术路线

系统前端采用 SPA 路由组织页面，后端以 FastAPI 提供模块化 API，画像、简历、面试数据通过 JSON 存储与转换器打通。

前端展示层

统一导航、模块页面和面试房间状态展示。

  • frontend/index.html 作为 SPA 入口。
  • router.js 通过 hash 路由切换画像、简历、面试和记录页。
  • 画像对话、简历上传、面试设置、语音房间分模块实现。

后端服务层

按业务边界拆分画像、简历、面试和 LLM 配置。

  • app/main.py 负责应用创建、CORS、静态资源和路由注册。
  • app/routers 提供 HTTP 入口。
  • app/services 封装 LLM、抽取、追问策略和评估逻辑。

数据衔接层

画像和简历不是孤立结果，而是面试输入。

  • profile_converter.py 同步画像到面试画像库。
  • candidate_converter.py 同步简历结果为候选人档案。
  • interview_store.py 维护面试索引和单场记录。

关键数据对象

系统的可追溯性来自明确的数据结构：每个模块都输出结构化对象，面试记录会保存过程和快照。

数据对象 来源 典型字段 进入面试后的作用
岗位画像 画像 Agent / JD 解析 company_context、signal_dimensions、must_have、anti_profile 决定考察维度、问题优先级和风险验证方向。
简历解析结果 简历流水线 claims、objective_experiences、project_experiences、blind_spots 把候选人的项目、技能、经历和盲点转成追问依据。
外部足迹 GitHub / 博客抓取 repositories、languages、recent_activity、blog_titles 补充简历之外的公开证据，辅助核验技术真实性。
面试记录 AI 面试引擎 plan、answers、follow_ups、evaluation、snapshots 保留完整过程，支持复盘、人工审核和后续模型优化。

实现亮点

这些点可以直接对应代码结构和系统行为，说明项目不是页面拼接，而是围绕招聘评估问题做了完整工程设计。

证据驱动

问题生成同时使用画像标准和候选人证据，避免只问通用题。

模块闭环

画像保存和简历解析会自动同步到面试模块，减少重复录入。

可降级运行

LLM、OCR、语音服务不可用时仍保留基本解析、文字面试和记录能力。

可扩展边界

后续接数据库、企业 ATS、评分 Rubric 或新模型供应商时边界清晰。

API 能力概览

四组 API 覆盖画像、简历、面试和模型配置，前端页面通过这些接口完成完整业务链路。

模块 核心接口 能力说明
画像模块 POST /api/portrait/chat
POST /api/portrait/save-profile		 完成画像对话、JD 解析、画像生成和保存同步。
简历模块 POST /api/resume/parse
GET /api/resume/results		 上传文件并输出结构化简历结果，解析成功后生成面试候选人。
面试模块 POST /api/interview/start
POST /api/interview/answer
POST /api/interview/end		 启动面试、获取问题、提交回答、生成追问和综合评估。
模型配置 GET /api/llm/config
POST /api/llm/test		 支持前端配置模型地址、模型名称和连接测试。

后续完善方向

基于当前闭环，后续可以继续增强评估可信度、数据管理能力和真实招聘场景适配。

评估量表

数据存储升级

将 JSON 文件存储替换为 SQLite、PostgreSQL 或 MongoDB，支持更多记录和查询。

人工复核

阶段成果结论

当前系统已完成招聘评估链路的核心闭环：岗位画像输入、简历证据输入、AI 面试输出和记录复盘。
